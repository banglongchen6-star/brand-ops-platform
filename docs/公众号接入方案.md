# 公众号（官方账号）接入「选题 → 参考 → 创作」全流程方案

> 状态：规划文档，不含实现
> 编写时间：2026-04-24
> 所属模块：内容运营 → 热点发现 + AI 创作区

---

## 一、为什么要写这个

现在工作台里公众号这个平台只是一个**空壳**：chip 能勾选、但没有数据流进来；子 Tab「手动录入」虽然有批量导入代码，但公众号链接的抓取成功率不高，整条链路实际走不通。

目标是让公众号和抖音、小红书一样成为**一等公民**，真正走完：
- **选题**：每天看到有价值的公众号爆款
- **参考**：对选中的爆款 AI 拆解，沉淀结构/钩子/套路
- **创作**：AI 输出**公众号图文稿**（不是视频脚本）给自家官号发稿用

## 二、当前公众号的状态（现状盘点）

| 环节 | 现状 | 问题 |
|------|------|------|
| 平台配置 | 已注册 `slug=weixin`、`source=manual`，默认 `enabled=false` | 无数据源 |
| 热榜数据 | 无 | DailyHot 没覆盖公众号 |
| 手动录入 | 代码已实现：粘贴多条链接→批量抓元信息 | 公众号链接（mp.weixin.qq.com）反爬严重，抓取成功率低 |
| AI 拆解 | 拆解 prompt 是通用的（偏短视频） | 图文场景维度不贴切（如"结构"侧重开头节奏 vs 段落切分） |
| AI 创作 | 输出字段是 `title/hook/script/key_points/cta/hashtags` | 视频脚本字段，不是公众号图文需要的（正文、小标题、配图提示） |

**结论**：代码基建一半有、一半没有；真正动作要从数据源 + 拆解/创作提示词两端改。

## 三、完整链路应该长什么样（目标态）

```
┌──────────────── 选题 ────────────────┐
│ ① 运营每天手动录入 3-5 条爆款公众号文章（URL + 截图/摘要）│
│    或链接批量粘贴，系统自动抓正文（改造后成功率提升）   │
│    → 落库 content_trends（source_type=manual）        │
└──────────────────────────────────────┘
              ↓
┌──────────────── 参考 ────────────────┐
│ ② 运营在「我的收藏」勾感兴趣的，点 AI 拆解             │
│    拆解 prompt 走「图文分支」：分析标题党套路、        │
│    开头 3 行钩子、段落节奏、结尾转化引导              │
│    → 结果入 content_hit_factors（加 content_type 字段）│
└──────────────────────────────────────┘
              ↓
┌──────────────── 创作 ────────────────┐
│ ③ AI 创作区选中爆款作参考，选「目标平台=公众号」       │
│    输出格式切换为图文稿：                             │
│       · 标题（主标题 + 副标题）                       │
│       · 导语（50-100 字引入）                         │
│       · 正文（含小标题分段）                          │
│       · 配图建议（每个小节给 1 张图的描述）           │
│       · 结尾 CTA（引导关注/预约/购买）                │
│    → 运营复制 → 去公众号后台排版发稿                  │
└──────────────────────────────────────┘
```

## 四、按环节拆解

### 4.1 选题：数据怎么进系统

公众号没有官方开放 API，方案从易到难四条：

| 方案 | 投入 | 数据覆盖 | 可靠度 | 推荐 |
|------|------|---------|--------|------|
| **A. 纯手工录入** | 0（已有界面） | 完全依赖运营手动 | 100% | ⭐ Phase 0 即可用 |
| **B. 链接粘贴抓取（改造现有）** | 小 | 依赖运营每天收集链接 | 70-90%（取决于抓取） | ⭐ Phase 1 |
| **C. 订阅 RSS 镜像** | 中 | 可自动化，但只能覆盖有镜像的号 | 视服务商 | ⭐ Phase 3 再考虑 |
| **D. 第三方数据平台购买** | 大（年付费） | 广，实时 | 高 | 先不考虑 |

**推荐路径**：

1. **立刻能用**：运营每天早上把看到的 3-5 条爆款公众号链接粘到「手动录入」框里，回车导入
2. **改造手动录入**：现在抓取遇到公众号正文抓不全时会进 `need_manual` 状态让运营补，增加一个"贴截图自动 OCR 成摘要"的旁路（可选）
3. **目标公众号列表**：先让用户（你）列出 10-20 个你们关注的**目标竞品/同行/行业公众号**，这些号的爆款是优先录入对象

### 4.2 参考：拆解维度针对图文调整

现在 AI 拆解产出 10 个维度：hook / structure / emotion / topic_angle / audience / format / replicable_elements / adaptation_advice / difficulty / tags。

对公众号图文来说：

| 维度 | 通用 → 针对图文怎么调整 |
|------|-------------------------|
| hook | 不是"开头 3 秒"，改成"标题党套路 + 导语钩子" |
| structure | 段落节奏（而不是视频节奏）：开头、主体分几段、小标题、结尾 |
| emotion | 保留 |
| topic_angle | 保留 |
| audience | 保留 |
| format | 改成"图文类型"（干货科普 / 故事 / 评测 / 产品软文…） |
| replicable_elements | 拆出"可直接复用的标题模板"和"可复用的段落模板" |
| adaptation_advice | 针对"如何改写成音乐密码公众号能发的稿" |
| difficulty | 保留 |
| tags | 保留 |

**做法**：给拆解 prompt 加一个分支参数 `content_type ∈ {video, article}`，system prompt 文本略作调整。

**数据库**：`content_hit_factors` 不需要加字段（现有 10 个字段语义通用），只需额外加一个 `content_type` 字段标记"这条拆解是针对视频还是图文"，方便后续创作时匹配。

### 4.3 创作：输出形式切换

现在 AI 创作区输出的是**视频脚本**结构（hook/script/cta/hashtags）。对公众号图文，输出应该是：

```
主标题（吸睛、含数字或反差）
副标题（补充说明、可选）

导语（50-100 字，快速建立相关性，引出正文）

[小标题 1]
正文段落...

[小标题 2]
正文段落...

...（通常 3-5 个小节）

结尾
  · 金句总结（1-2 句）
  · CTA（关注 / 评论 / 预约试奏 / 到店体验）

配图建议
  · 封面图建议
  · 每个小节 1 张图的描述（为了美编出图时有依据）
```

**做法**：
1. 在 AI 创作区表单上，**目标平台**选到"公众号"时，表单结构切换（隐藏 hashtags、露出"小节数量"、"配图需求"）
2. 后端 `/api/content/generate-script` 根据目标平台分支，用不同 system prompt
3. 返回的 JSON 字段跟着切换；前端分"视频脚本视图" / "图文稿视图"

## 五、分阶段实施建议

为了不一口气吃太多，把改动拆 3 个 Phase。

### Phase 0：零开发，先跑起来（今天就能做）

1. 把公众号平台的 `enabled` 改成 true（或运营在平台管理里勾一下）
2. 你给自己拉一个「目标公众号清单」—— 10-20 个号，Excel 即可
3. 每天早上花 10 分钟从这些号挑 3-5 篇爆款（看阅读量+在看数），把文章链接粘到「手动录入」框
4. 能抓到的文章进入 `content_trends`，剩下的用当前界面手动补标题/描述
5. 在「我的收藏」里对感兴趣的点 AI 拆解（虽然 prompt 还没针对图文优化，但通用拆解结果至少能用）

**价值**：验证这个工作流对运营有没有真实帮助，再决定后面投入多少开发。

### Phase 1：专属字段 + 抓取改造（1-2 天开发）

- `content_trends` 加 `content_type` 字段（video / article，默认推断：微信号 url 自动打 article）
- 公众号链接抓取改造：用 mobile UA + 公众号正文选择器，把抓取成功率从 ~30% 提到 ~70%
- 抓不到时的「手动补录」界面保留
- 公众号在热榜卡片上显示"📄 图文 · XX 字"而不是"▶ 视频"

### Phase 2：拆解/创作 prompt 分支（1 天开发）

- `/api/content/trends/analyze` 根据 `content_type` 走不同 system prompt
- `/api/content/generate-script` 当 `platform=weixin` 时切换图文模板
- 前端 AI 创作区表单根据目标平台动态切换字段
- 图文稿视图分块展示，每块单独"复制"

### Phase 3（可选，未来做）：自动化

- 跑定时任务订阅 RSS 镜像（如果找得到靠谱源）
- 或者搞一个"截图+OCR → 自动转结构化"的链路

## 七、风险与注意事项

1. **公众号反爬**：微信对爬虫封得严，抓取任何文章都可能失败。**不要把自动化抓取当成常态**，手动录入兜底是必要的。
2. **版权**：拆解结果仅供**学习参考**，创作稿不能直接复制原文段落。Prompt 里要明确"学习结构、不抄正文"。
3. **调用成本**：千问 Coding 模型调用成本和响应速度跟 Claude 有差异，Phase 1 做完要观察 AI 拆解和创作的平均耗时。
4. **运营工作流的改变**：这套流程要求运营每天花 10-30 分钟做"收集 + 录入 + 点拆解"，要评估是否真的能替代现在金山文档的手工流程。
5. **目标公众号清单**：**这是最关键的前置输入**。没有这份清单，所有工具都是空的。

## 八、开发前需要你先决策的 3 件事

在开干之前请回答（不用现在回，记在脑子里）：

1. **目标公众号清单你有吗？大致多少个号？**
   - 如果 10 个以内 → Phase 0 手工即可
   - 30+ 个 → Phase 3 的自动化更有价值

2. **AI 生成的公众号稿是给谁看？**
   - a) 给内容部同事做「选题参考」，他们基于这份稿再手写 → 侧重"结构和角度"
   - b) 想让 AI 直接产出能发的稿，人工只做润色 → 侧重"正文完整度、语气贴近品牌"
   - 这两种目标决定了 Phase 2 prompt 的精细程度（a 简单，b 工作量大且效果不稳）

3. **自家公众号每周发几篇？**
   - 1-2 篇 → 这套工具主要是"选题库 + 参考"，不必自动化生产
   - 3+ 篇 → 值得把 AI 创作做到能用级别
